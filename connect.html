This page does not connect or reconnect QuickBooks. It is a static instruction page. Production authorization is not configured. Opening this address does not sign anyone in, does not start OAuth, and does not show a success result.

Separate sign-in service

The program that can actually sign the Owner in, send the browser to Intuit, receive the authorization code, and store tokens is oauth-service in the source repository. GitHub Pages does not run it, and Intuit must not send the authorization code to mapleridgevet.github.io. That service is not deployed and has no hostname yet. Until the Owner approves a hostname and starts it on the Company PC, this page cannot hand you off to a live sign-in.

What this address is

Intuit’s app settings ask for a connect/reconnect URL: the page a customer opens when connecting or reconnecting the app. This is that instruction page for CPA. It is not the OAuth redirect URI. Intuit’s OAuth server must send the authorization code to a separate redirect URI that can exchange the code for tokens. This GitHub Pages file cannot do that exchange.

CPA is an internal tool for the authorized Owner on a Company-controlled computer. It is not a public sign-in website. There is no web login on this site.

Current connection state

  • The connector in use is the sandbox / development setup on the authorized Company Windows PC.
  • That PC starts authorization with the local launcher authorize-quickbooks.ps1 in the connector folder.
  • The sandbox callback stays on that PC. It is not a link on this website, and it is not a production redirect URI.
  • A production HTTPS redirect URI is not configured. This site does not publish an authorization endpoint.

Owner-only sandbox authorization

Use these steps only on the Company Windows PC where the connector is already installed. Another computer cannot complete them.

  1. Sign in to the Company’s QuickBooks Online sandbox company in the browser on that PC, as the authorized Owner.
  2. Open the connector folder on that PC and run authorize-quickbooks.ps1.
  3. Use the QuickBooks consent screen that the launcher opens. Approve the connection only for the Company file you intend to connect.
  4. Leave the authorization code, tokens, client secret, and company ID on that PC. Do not paste them into email, chat, or this website.
  5. Stop if the launcher is missing, the consent screen does not appear, or the window reports an error. This page cannot repair that.

The Privacy Policy describes where that local process stores tokens: Credentials and token handling and where CPA runs.

Production reconnect is not available here

When a production connection exists, reconnecting means the Owner runs the local authorization flow again and Intuit returns a new authorization code to the configured production redirect URI. That URI is not this page. Until a production HTTPS redirect URI is registered and a process on the Company side can exchange the code for tokens, choose this page in Intuit’s form only as the place a person is sent to read these instructions. It does not re-authenticate the app.

Refresh-token expiry notices inside QuickBooks may link to whatever reconnect URL is saved in the developer portal. If this address is that URL, the notice will open these instructions. It will not renew tokens by itself.

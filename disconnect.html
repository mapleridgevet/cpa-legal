This page does not disconnect QuickBooks. It is a static instruction page. There is no disconnect button here, and this site cannot revoke tokens. If QuickBooks sent you to this address, the app is not disconnected until you finish the steps below. Anything after a question mark in the address is ignored. This page does not read, display, or store a company ID.

What this address is

Intuit’s app settings ask for a disconnect URL: the page a person reaches after they disconnect the app from a QuickBooks Online company. For an app that does not use Intuit single sign-on, Intuit’s current app-settings documentation allows that destination to be a static page that tells the user they have disconnected, with steps to reconnect if the disconnect was unintended.

This page is that static notice for CPA. It is not an OAuth redirect URI and it does not call Intuit’s token-revoke API. Revoking tokens from the app’s side has to happen on the Company PC, where the tokens are stored. The oauth-service program is the piece that can send Intuit’s revocation request after the Owner signs in. It is not running on this GitHub Pages site, and this page still has no revoke button.

1. Disconnect the app inside QuickBooks Online

Sign in as a QuickBooks Online admin, or as the user who connected the app. Intuit’s current U.S. help says:

  1. Go to Integrations and select Manage integrations.
  2. Find CPA (or the app name shown in the Intuit developer portal).
  3. Open the Action menu and select Disconnect. If that item is missing, open Settings for the app and use the Disconnect button there.
  4. Complete Intuit’s short questionnaire and select Confirm Disconnect.

Menu labels can change. Use Intuit’s article Disconnect an app and change subscription in QuickBooks if the screen does not match these steps. QuickBooks may then send the browser to this page. Landing here is not itself the revocation.

2. Stop the local connector and remove its token file

On the authorized Company Windows PC:

  1. Stop the local connector if it is still running. Closing the window that authorize-quickbooks.ps1 opened is the start; also end any connector process that is still running on that PC.
  2. Remove the local token store the connector uses. The Privacy Policy describes it as a local configuration or token file on that PC, not a database on this website.
  3. Do not open the file and paste its contents into email, chat, or a browser. Do not send the client secret, refresh token, or company ID to anyone.
  4. This website cannot see that file and cannot delete it for you.

Intuit’s OAuth documentation says that when a user disconnects, the app needs to revoke its access and refresh tokens by calling Intuit’s revocation endpoint. The local connector is the only CPA component that can do that, and production authorization is not configured. Deleting the local token file stops this PC from reusing a saved token. It does not by itself prove that Intuit has revoked the grant. Do step 1 in QuickBooks as well.

If the disconnect was unintended

Reconnecting is not offered on this page. The Owner can read Connect or reconnect QuickBooks. That page explains the current sandbox launcher. It also states that a production reconnect cannot be completed from this website.
